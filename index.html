01用户与问题

学习环境出问题，往往是"不知不觉"的

目标用户是经常在图书馆、宿舍、教室、咖啡馆之间换地方自习的大学生。光线变暗、周围变吵都是慢慢发生的，等到觉得累、分心时，往往已经低效地学了很久。

痛点 1

环境问题难以察觉

人眼会自动适应昏暗的光线，人也会逐渐"习惯"噪音，所以很少有人会主动意识到环境已经不适合学习了。

痛点 2

选地方全凭感觉

"去图书馆还是在宿舍学？"、"晚上学效率更高吗？"这些问题很少有客观依据，只能靠印象判断。

痛点 3

分心了却找不到原因

计时类 App 只能记录"专注了多久"，却不能解释"为什么没专注下去"，用户也就不知道下次该改什么。

需要验证的核心假设

  1. 给出具体分数和可执行的建议（而不是"光线不好"这样的笼统判断）后，用户会真的去调整环境：开灯、换位置、戴耳机。
  2. 用环境数据解释专注效果，比单纯计时更能帮助用户找到适合自己的学习地点和时段。

02从 v1 到 v2

复盘课程作业版，重新定义需求

v1 是我在 UCL CASA0015 课程中用 Flutter 做的手机 App。回头复盘时，我发现它更像一个"传感器演示"，还没有真正解决用户的问题。v2 在此基础上重做为网页版。

v1 的做法问题v2 的改动
只用亮度判断环境学习环境不止光线，噪音同样关键加入麦克风噪音检测，光线和噪音综合评分，并考虑短板效应
天气固定显示伦敦，且不参与判断对其他城市的用户没有意义按定位获取当地天气，并作为建议的上下文（如"外面阴天，窗边光线也不够"）
建议只有"好 / 中 / 差"一句话用户不知道具体该做什么给出 1–3 条可执行建议，带目标数值（如"桌面照度最好在 300–500 lx"）
检测是一次性的学习过程中环境会变化专注计时 + 持续监测：环境持续变差超过 20 秒就提醒

历史只有流水记录和一条折线数据记了，但没有给出结论历史洞察：最适合的地点和时段、不同环境下的专注完成率
需要安装 App；天气 API key 写在代码里试用门槛高，还有密钥泄露风险网页版打开即用；改用免 key 的 Open-Meteo 天气服务

03需求取舍

先做什么，不做什么

按"对用户的价值"和"实现成本"排序：高价值、低成本的先做；有价值但会分散焦点、或需要先验证的，明确地放到后面。

P0 · 先做

价值高，成本低

  • 噪音检测 + 综合环境分
  • 按定位获取天气
  • 可执行的具体建议
  • 演示模式（降低试用门槛）

P1 · 接着做

价值高，成本较高

  • 专注计时 + 环境变差提醒
  • 历史洞察：最佳地点 / 时段
  • 地点档案 + 自习地图
  • 状态反馈 + 个性化评分

之后再做

需要先积累数据

  • AI 学习助手（见路线图）
  • 校园"安静地图"：汇总大家的地点档案

明确不做

以及原因

  • 把室外温度算进分数：室外温度不等于室内温度，算进去反而会误导用户
  • 账号和云同步：环境数据比较敏感，验证阶段存在本地就够了
  • 排行榜等社交功能：会和"专注"这个核心目标冲突

04评分模型

把"感觉"变成可解释的分数

评分规则全部公开、可以解释，用户能看懂为什么得了这个分，也知道怎么提高。

短板效应

总分取两项的平均，但不超过较低一项 + 15 分。环境很吵时，光线再好也不应该显示"适合专注"。

避免误报

专注时，环境分连续 20 秒低于 60 分才提醒，回升到 70 分以上才解除，不会因为一声咳嗽就打断用户。

因人而异

专注后反馈状态，积累 5 次以上后，用"状态好"那几次的噪音水平平移噪音曲线。有研究发现适度背景声有助于创造性任务（Mehta 等，2012），所以"最佳噪音"不该一刀切。

坦诚说明局限

摄像头会自动曝光，麦克风也没有校准，所以读数是估算值，适合判断"偏暗 / 适宜 / 偏强"这样的区间，不能替代专业测量仪器。

05竞品与差异化

别的产品管时间，StudySync 管环境

类型代表产品解决什么缺什么
专注计时Forest、番茄 ToDo管住时间和行为：计时、锁手机、游戏化激励不关心你在什么环境里学
白噪音潮汐、Noisli掩盖噪音不判断环境本身好不好，也不建议换地方
测量工具分贝仪、照度计类 App给出原始数字只有数字，没有"对学习意味着什么、该怎么做"
差异 1

把数字变成行动

不是"噪音 62 dB"，而是"环境嘈杂，戴上耳机或换到更安静的地方"，并在专注中持续提醒。

差异 2

记住每一个具体地点

精确到"学校门口那家咖啡馆"，而且能看出它"上午安静、下午变吵"。用得越久，地点档案越有价值，这是数据积累带来的壁垒。

差异 3

越用越懂你

通过专注后的状态反馈，学习"你"适合多大的背景声，而不是给所有人套用同一个标准。

我也清楚它作为独立产品的门槛不高。更现实的路径是作为专注类产品的一个功能模块，比如在开始计时前加一步"环境检测"；如果独立发展，壁垒来自个人地点档案和汇总后的校园"安静地图"。

06成功指标

如果正式上线，我会这样衡量

北极星指标

每周高质量专注时长

环境分 ≥ 80 时完成的专注分钟数。它同时反映了"用户在专注"和"环境是好的"两件事。

检测 → 开始专注的转化率

看到环境分之后，用户是否真的开始学习。

提醒后的环境回升率

收到提醒后 2 分钟内环境分回升的比例，用来验证假设 1：建议能否促使用户行动。

个性化评分的准确度

环境分与用户主观反馈的一致程度，开启个性化前后对比，用来验证"越用越懂你"是否成立。

专注完成率

分环境档位对比，用来验证假设 2：好的环境是否带来更高的完成率。

07路线图

下一步

近期

  • 麦克风校准向导：在已知安静的环境里校准偏移，提高 dB 估算精度
  • 把光线也纳入个性化：有人喜欢暖光，有人需要更亮的冷光

中期

  • AI 学习助手：基于历史记录，用大模型生成每周复盘和个性化建议，比如"你周二晚上在宿舍的完成率最低，试试改去图书馆"。模型通过服务端调用，API key 不暴露在前端。
  • 校园"安静地图"：在个人地点档案的基础上，匿名汇总大家在各自习点的环境分，出发前就能选好地方

长期

  • 和原生 App 同步数据，用上手机的真实光线传感器
  • 接入日历，把高难度任务自动安排到你环境最好的时段
